# iamtalkernote 안드로이드 (시작 단계)

컴퓨터의 iamtalkernote 와 **같은 노트 폴더(마크다운 파일)** 를 폰에서 읽고 고치는 앱입니다. 지금은 첫 단계(0.1.0)이고, **아직 기기나 에뮬레이터에서 실행해 보지 못했습니다**(빌드만 확인).

## 지금 되는 것
- 노트 폴더 고르기(저장소 접근 프레임워크 SAF, 한 번 고르면 기억) — 하위 폴더까지 `.md` 를 찾습니다. 점으로 시작하는 폴더(`.history` `.trash` `.resources`)와 `_resources` 는 데스크톱 앱처럼 건너뜁니다.
- 목록(수정 시각 최근 순), 검색(공백 = AND, 기본은 제목, *본문까지 검색* 을 켜면 본문도), 새 노트, 열어서 고치고 저장(뒤로 가면 자동 저장).

## 아직 없는 것 (순서대로 할 일)
1. 머리말(`updated`/`created`/`tags`)을 읽어 날짜·태그로 정렬·검색 — 지금은 파일 수정 시각을 씁니다.
2. 마크다운 보기(렌더링), 그림(`.resources`) 보기.
3. 색인 DB(SQLite)로 본문 검색 속도 — 지금은 켤 때마다 메모리에 읽습니다. 노트 1.4만 개는 폰에서 느릴 것입니다.
4. 동기화 충돌 처리 — 아래 참고.
5. 가져온 파일(pdf 등)의 태그·메모는 앱 DB 에만 있어서 폰에 없습니다. 파일(예: `.imported-meta.json`)로 내보내는 설계가 먼저 필요합니다.

## 동기화에 대한 생각
- 파일 전송은 **폴더 동기화 도구(예: Syncthing)** 에 맡기고, 앱은 같은 폴더를 읽고 씁니다. 그래서 자체 서버가 필요 없고, 노트 파일이 원본이라는 원칙이 그대로입니다.
- 양쪽에서 같은 노트를 고치면 Syncthing 이 `…sync-conflict-…md` 같은 이름의 복사본을 남깁니다. 앱이 이런 파일을 알아채서 *충돌* 로 보여 주고 노트 버전으로 합치게 하는 것이 다음 큰 일입니다(데스크톱의 *앱 밖 수정 감지* 가 그 안전망).
- 용량: 폰에는 폴더 전체가 아니라 **고른 노트북만** 받는 편이 현실적입니다(Syncthing 의 폴더·무시 규칙으로 가능).

## 빌드
JDK 17 + Android SDK(34)가 필요합니다. 한글 경로에서도 되도록 `gradle.properties` 에 `android.overridePathCheck=true` 를 켜 두었습니다.

```
cd android
./gradlew assembleDebug        # → app/build/outputs/apk/debug/app-debug.apk
```

`local.properties` 의 `sdk.dir` 은 사용자마다 달라서 저장소에 없습니다(환경 변수 `ANDROID_HOME` 도 됩니다).
